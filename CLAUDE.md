# CallSentry — working notes

Self-hosted AI voice receptionist. Read `README.md` first for what it does; this
file is about how to change it without breaking it.

## Commands

```bash
make bootstrap        # first run: env + up + migrate + models + seed
make up / down        # start / stop
make migrate          # apply migrations
make test             # backend suite
make lint             # ruff + mypy
make logs s=app       # tail one service
```

Both Python services run natively too (Docker is slow to iterate against):

```bash
cd app && uv venv --python 3.12 .venv && uv pip install -e ".[dev]"
ENCRYPTION_KEY=<base64-32-bytes> JWT_SECRET=x INTERNAL_API_TOKEN=x pytest -q
```

## Architecture rules

**Conversation logic lives in `app`, never in `pipecat`.** The voice container
transports audio and calls `/internal/turn`. If you find yourself adding an
`if intent ==` to `pipecat/`, it belongs in `agents/voice_agent.py` instead —
that module is testable without audio, and it shares a DB session and provider
registry with everything else.

**Every inference call goes through `core/providers.py`.** Don't call Ollama or
Anthropic directly from a route or an agent. The registry is what makes
`local → cloud → mock` work, records attempts on the call's `provider_log`, and
short-circuits an already-failed provider for the rest of the call.

**The mock tier must always succeed.** It exists so a dead model degrades the
call instead of dropping it. When you add a provider chain, the mock handler
returns something the caller can act on — for anything ambiguous, that means
escalating to a human, never improvising.

**Never read `*_enc` columns directly.** Use `services/credentials.py`. It binds
the business ID as AES-GCM additional authenticated data on both sides, which is
what stops a ciphertext copied between tenant rows from decrypting.

## Claude API specifics

`services/llm.py` is the only place that talks to Anthropic. Two things there
are load-bearing and easy to undo by accident:

- **`thinking={"type": "disabled"}` on the realtime path.** Claude Sonnet 5 runs
  adaptive thinking when the field is *omitted*, which generates reasoning
  tokens before any text — heard by the caller as dead air. Offline work
  (summaries, sentiment) passes `realtime=False` and leaves thinking on.
- **No `temperature` / `top_p` / `top_k`.** Sonnet 5 rejects non-default values
  with a 400. Steer tone through the system prompt.

Also: check `stop_reason == "refusal"` before reading `content` — a decline
returns HTTP 200 with empty or partial content.

## Adding things

**A provider:** add a `ProviderSpec` to `CATALOGUE` in `core/providers.py`, add
a handler to the relevant service's `registry.run(...)` dict, and extend
`_configured()` so it reports *why* it's unavailable. The dashboard renders that
string verbatim.

**A migration:** `make revision m="..."`. Check the autogenerated file — pgvector
columns and JSONB server defaults are the two things Alembic tends to get wrong.

**A dashboard chart:** load the `dataviz` skill and validate the palette with its
script before writing chart code. The existing analytics palette is validated
against this dashboard's actual panel colour (`#131a23`), not a generic surface.

## Gotchas

- **`EMBEDDING_DIM = 768`** in `models/kb.py` is pinned to nomic-embed-text.
  Changing the embedding model means a migration *and* reindexing every
  document — there is no way to mix dimensions in one column.
- **`audioop` is a test oracle, not a dependency.** It's deprecated and gone in
  3.13, which is exactly why `pipecat/agent/audio.py` implements the μ-law
  tables itself. The conformance test skips cleanly when it's absent.
- **Twilio webhooks are retried.** Anything they touch must be idempotent —
  that's why `calls.provider_call_id` is unique and per-call cost is recomputed
  from the ledger rather than incremented.
- **Call state lives in Redis with a TTL**, not in a table. It's worthless after
  the call, and the TTL bounds the damage from a missing hangup webhook.
- **Business hours fail open.** A malformed `business_hours` JSON answers calls
  normally rather than silently making a business unreachable.

## Things deliberately not done

Listed in the README's *Known limitations*. The two most likely to be mistaken
for bugs: warm transfer is signalled (`transfer_to`) but not dialled, and
`analytics.top_topics` counts keywords rather than using the topic labels the
analysis step already produces.
